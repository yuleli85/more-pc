# 多台电脑 WorkBuddy 总控

一个网页交活，交给空闲的电脑上的 WorkBuddy 去干。电脑不用在同一个网络：每台只主动往外连总控，不用公网 IP，也不用改路由器。

## 两种派法
- **派给空闲的电脑**（默认）：一件活只给一台。挑手上没活、CPU 最闲的那台；都在忙就先排着，谁先空下来谁接。勾「每行算一件活」可以一次交一批。电脑本身很忙（CPU 超过 85%，比如有人在用）先不派；掉线的电脑，派给它还没开始的活会退回去给别的电脑。
- **每台都做一遍**：同一条指令，选中的电脑各做一次。
- 左边勾了电脑，就只在勾的这几台里派；不勾就是全部。

## 接着某条会话做（带上下文）
- 发任务区有一行「会话」，默认是**新会话**。点「选一条旧会话」会列出最近跑过的会话（哪台电脑、任务摘要、目录、时间），挑一条就接着它做。
- 选了会话之后，**机器和目录自动锁死**：会话只存在于跑它的那台电脑、那个文件夹里，换台电脑或换目录就接不上了。
- 两种会话不一样：
  - **命令行跑的**：能让命令行精确续上那一条（`--resume`），上下文原样带过来。这类任务会走命令行，WorkBuddy 客户端「自动化」列表里不会有这一条，但会话本身在客户端里能回看。
  - **客户端跑的**（大多数）：客户端的会话库（`~/.workbuddy`）和命令行的会话库（`~/.codebuddy`）不通用，登录态也是各管各的，命令行读不到。这种情况会自动改成在客户端**开一条新会话**，把上一轮的结论带过去当上文，并在过程里写明——上下文不会原样继承。
- 任务详情里每台卡片上都有「接着这条会话」按钮，点一下就把那条会话填回发任务框；会话 id 也能一键复制。
- 注意：真正的续接不再用「接着上一轮聊」那个勾（那是让命令行自己猜最近一条，多台同时干活时容易猜错）。

## 定时执行（到点自动干，不用人盯着）
- 左侧有第三个页签「定时」。点「新建定时任务」，写好指令、选好频率，到点总控自动按存好的配置派活，跟人手动点「发出去」完全一样。
- 四种频率：
  - **每天固定时间**（例如每天 08:30）
  - **每周固定几天**（勾星期几 + 时间，例如每周一、三 21:00）
  - **每隔一段时间**（最短 5 分钟，例如每 2 小时）
  - **到点只跑一次**（指定一个具体时刻，跑完自动停用）
- 每条都能单独设：派活方式（派给空闲的 / 每台都做一遍）、目标电脑（不勾＝全部）、优先级、专家、模型、Git 同步、执行目录、「每行算一件活」「按行接力」。
- 列表上每条都有「立即跑一次」——不等到点，立刻照这份配置发一次，用来试效果；**手动跑不会打乱原来的周期**。
- 「停用 / 启用」临时关掉某条；「改」可以改配置；「删」删掉（已经发出去的任务不受影响）。
- 到点发不出去（比如一台电脑都没连着）不会静默失败，列表上写明原因和时间。
- **总控关机或重启时错过的档口不补发**：循环类的顺延到下一个正常时刻，只跑一次的那条会标成「错过了」并自动停用 —— 避免一开机就刷屏。
- 自动发出去的任务在任务列表里带一个「定时」标记，双击可以看各台执行结果；提示词也照样记进「提示词」页。
- 频率和配置存在总控的 `data/state.json` 里，重启不丢。

## 技能共享（一台开发，其它电脑几秒内就有）
- 左侧第四个页签「技能」。在任何一台电脑上开发或修改用户级技能（`~/.workbuddy/skills/<技能名>/`），**不用做任何操作**，几秒内其它电脑就自动装好、开始能用。
- **怎么找技能**：顶部搜索框按名字搜（不区分大小写，打字时会自动筛）；右边可以按「来源电脑」「安装状态」「某台电脑」筛，还有「只看没装齐」——一眼看出哪个技能还没同步到所有在用的电脑上。
- **点技能名展开**，能看到这个技能里有哪些文件、每个多大。
- 全自动双向：A 改了 → B、C 自动更新；B 又改了 → A、C 跟着更新。**谁最后改就以谁的为准**（按文件内容算版本，不是按时间戳硬猜）。
- 只同步用户级技能（`~/.workbuddy/skills/`），项目里的 `.workbuddy/skills/` 不同步；WorkBuddy 商店装的插件技能不受影响。
- **删除不自动同步**：在某台电脑上把技能文件夹删了，其它电脑照旧；这台自己也不会再被自动装回来。想让它装回来，在「技能」页点「推送到全部」。
- 「技能」页上每台电脑一个标签（已装 / 版本不同 / 已删 / 未装），点某个标签＝只从那台电脑上删掉（其它电脑不动）。
- 「停止共享」＝总控不再分发这个技能，各台电脑上已有的文件不动；「彻底删除」＝连各台电脑上的文件一起删。
- 限制：单个技能最大 2MB、最多 200 个文件（超了会被跳过，页面上不会出现）；技能内容在总控的 `data/skills/` 里，是明文 —— 别把密码写进技能里。
- 需要连接程序 1.11.0 以上（老版本会自动升级）。

## 接力（开发时一步接一步）
- 勾「按行接力」：后一行等前一行做完才开工，自动带上前一行的结果，优先交给做前一行的那台电脑（文件就在那台，不用同步）；那台正忙才交给别的空闲电脑。
- 任务详情里点「接着这件做」：新发的活接在这件后面，规则同上。
- 勾「代码用 Git 同步」：由每台的连接程序自己做（不靠 AI 记得跑）——开工前 git pull 拿最新代码，做完自动 git commit 并 push（别的电脑先推了会先合上再推）；拉取冲突、推送失败都会标成「没做成」并写明原因。接力换了电脑时，下一台拿到的也是最新代码。
- 某台干到一半关机或断网超过 3 分钟：派给空闲的活会转给别的电脑重做，那台回来会被叫停，不会两台重复干。
- 前一步没做成或被停下，后面接力的不会开工。

## 装到云主机（一行）
在 Linux 云主机上（root 或有 sudo）：`bash <(curl -fsSL https://lingmao-download.bagayalu.cc/wb-hub-install.sh)`
装到 /opt/wb-fleet，系统服务 wb-fleet-hub 开机自启，默认端口 8790（被占往后顺延）。跑完屏幕上列出总控网页地址、每台电脑的接入命令、装终端的命令。重跑就是升级（口令和任务记录保留）；末尾加 `check` 只看状态，加 `uninstall` 卸载（数据先留底到 /root）。网页打不开就在云厂商安全组放行这个端口。云主机只派活，不干活。

## 终端（在任何一台电脑上派活、看状态和结果）
- Mac / Linux：`curl -fsSL https://lingmao-download.bagayalu.cc/wb-term.sh | bash -s -- 总控地址 口令`
- Windows（PowerShell）：`& ([scriptblock]::Create((irm https://lingmao-download.bagayalu.cc/wb-term.ps1))) 总控地址 口令`
- 用法：`wb` 看各台状态和最近任务；`wb 派 "要干什么"` 派给空闲的电脑并实时显示进度和结果（`--每台` `--给 A,B` `--紧急` `--文件夹 X` `--接在 任务号` `--git` `--每行一件` `--不等`）；`wb 看 任务号`；`wb 停 任务号`；`wb 任务`。

## 组成
- `hub.js`：总控（网页＋中转站），放在一台有公网的服务器上。
- `agent.js`：每台电脑上的连接程序，领到活交给本机 WorkBuddy 的内核（CodeBuddy 命令行）去干。
- `wb.js`：终端（wb 命令）。
- `join.sh` / `join.ps1`：每台电脑的一行加入命令（Mac/Linux、Windows），总控网页「加电脑」里直接复制。
- `update-embed.ps1` / `update-embed.sh`：升级用的脚本模板，总控会在下发升级指令时把全文塞进指令里。
- 只用 Node 18 以上版本自带的模块，不用另外装依赖。

## 升级各台的连接程序（不用去那台电脑）
网页右上角「升级连接程序」：给还没到最新版的在线电脑各发一条升级指令，一分钟内陆续升好，升级时会短暂离线再自动回来。也可以只升某几台，或者直接调接口：
```
curl -X POST "http://<总控>/api/upgrade?key=<口令>" -H "Content-Type: application/json" -d '{}'
```
- 默认只升「版本不是最新」的机器；要强制重升就带上 `"force": true`。
- 连接程序升级后（1.7.0 起）还支持自动更新：老版本连上来、手上没活时会自己补一条升级，一小时最多试一次。所以离线的机器开机连上后会自动升级。
- 某台一直显示「已发出、没接手」= 它的连接程序卡在一个旧活上，调一次 `POST /api/machines/<机器名>/unstick` 解卡，再重发。
- 升级不了的两个常见原因：那台电脑的 WorkBuddy 命令行没登录（远程跑任何任务都会报 `Authentication required`，只能在那台机器上 `codebuddy` 后输入 `/login`）；或者还没接入过总控（没有 `~/.wb-fleet/agent.js`）。

## 先在自己电脑上跑起来试
```
cd WorkBuddy多台总控
node hub.js
```
打开它打出来的地址（`http://127.0.0.1:8790/?key=口令`，要装 Node 18 以上），点「加电脑」复制那一行命令，在同一台电脑的另一个终端里运行，这台就接进来了；发一句「建 hello.txt 写 ok」看能不能做完。
本机跑的总控只有这台（和同一个局域网里的）电脑连得上；5 台在不同网络就用公网上那个总控，或照下面放到自己的服务器。

## 放到自己的服务器
```
PUBLIC_URL=https://你的域名 PORT=8790 node hub.js
```
第一次启动会生成口令，存在 `data/key.txt`（网页登录口令也在 `data/pass.txt`）。打开 `https://你的域名/?key=口令` 会自动登录一次（地址栏里那串随即被清掉），进去后点「加电脑」，把那一行命令复制到每台电脑的终端里运行。登进去以后建议先把网页登录口令改成自己的（见下面「谁能打开这个网页」）。

## 谁能打开这个网页（登录）
- 打开网页要先输「网页登录口令」。第一次就是 `data/key.txt` 里那串（会自动写进 `data/pass.txt`），用原来的口令登进去就行。
- 登录后浏览器会记住 30 天，这期间直接打开地址即可；换电脑、换浏览器要重新输。
- 改口令：右上角「加电脑」→ 最下面「安全：网页登录口令」，填现在的一串 + 新的一串。改完立刻生效，别处已经登录的浏览器会被踢下线。
- **改过之后，带 `?key=` 的旧链接就作废了**（不再自动登录），只有知道新口令的人进得来 —— 链接外泄过就改一个。
- 连错 5 次锁 5 分钟，防着有人拿脚本一直猜。
- 两个口令分工不同：**机器口令**（`data/key.txt`）给连接程序和各台电脑用，**网页登录口令**（`data/pass.txt`）给人用。改网页口令不影响已经接进来的电脑，不用重装。
- 想再严一点：云厂商安全组只放行你自己的 IP；或者在前面套一层 Nginx + HTTPS（这时启动加 `TRUST_PROXY=1`，登录限速才认得真实来源 IP）。

## 要注意
- 口令分两种，都别外传：**网页登录口令**（人进门用，可随时改）、**机器口令**（`data/key.txt`，给各台电脑接入用，改了每台都要重跑加入命令）。
- 每台电脑第一次要登录一次 WorkBuddy 命令行：运行 `codebuddy`，输入 `/login`，用 WorkBuddy 的账号登录。
- Mac 第一次读桌面、文稿、下载这几个文件夹时，系统会弹窗，点一次「允许」。
- 电脑要开着、联网；断网后会自动重连，排着队的活不会丢。
- 每台默认在「WorkBuddy-tasks」文件夹里干活，发指令时也可以指定别的文件夹。
